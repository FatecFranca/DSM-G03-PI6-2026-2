🏷️ Tipo Suporte - API Documentation

Gerenciamento completo de tipos de suporte. Endpoints para cadastro, listagem, alteração e controle de status, com permissões específicas para gestores.

Status do Tipo de Suporte

ATIVO ↔️ INATIVO
📋 Regras de Transição:
  • ✅ ATIVO → INATIVO: Permite inativar, desde que não haja chamados em andamento vinculados
  • ✅ INATIVO → ATIVO: Permite reativar a qualquer momento
  • ⚠️ Ao inativar um tipo com chamados em andamento, a API retorna erro
  • 📌 Tipos inativos não podem ser selecionados para novos chamados

Endpoints Protegidos (Requer Token JWT)

POST / 🔑 GESTOR

Cadastra um novo tipo de suporte. Apenas gestores da unidade.

📥 Request Body

UnidadeId* ID da unidade (deve ser a do gestor)
TipSupNom* Nome do tipo de suporte
TipSupStatus ATIVO ou INATIVO (default: ATIVO) 
{
  "UnidadeId": 1,
  "TipSupNom": "Suporte de Rede",
  "TipSupStatus": "ATIVO"
}

📤 Responses

201 Created 400 Bad Request 401 Unauthorized 403 Forbidden 404 Not Found 409 Conflict
⚠️ Validações:
  • Gestor deve estar ATIVO
  • Unidade deve estar ATIVA
  • Nome do tipo deve ser único na unidade
  • Gestor só pode cadastrar na sua própria unidade
PUT /{id} 🔑 GESTOR

Altera dados do tipo de suporte. Apenas gestores da unidade.

📥 Parameters

id* ID do tipo de suporte (path)

📥 Request Body

TipSupNom Novo nome (opcional)
TipSupStatus ATIVO ou INATIVO (opcional) 
{
  "TipSupNom": "Suporte Avançado",
  "TipSupStatus": "INATIVO"
}

📤 Responses

200 OK 400 Bad Request 401 Unauthorized 403 Forbidden 404 Not Found 409 Conflict
⚠️ Validações Especiais:
  • Não é possível inativar se existirem chamados em andamento vinculados
  • Nome deve ser único na unidade (ignorando o próprio registro)
  • Gestor só pode alterar tipos da sua própria unidade
PATCH /{id}/status 🔑 GESTOR

Altera apenas o status do tipo de suporte. Endpoint específico para ativar/inativar.

📥 Request Body

TipSupStatus* ATIVO ou INATIVO 
{
  "TipSupStatus": "INATIVO"
}

📤 Responses

200 OK 400 Bad Request 401 Unauthorized 403 Forbidden 404 Not Found
⚠️ Restrições:
  • Para INATIVAR: não pode haver chamados em andamento vinculados ao tipo
  • Para ATIVAR: não há restrições adicionais
  • Gestor só pode alterar status de tipos da sua própria unidade
  • Unidade do tipo deve estar ATIVA

Modelo de Dados - Tipo Suporte

TipSupId Integer - ID único do tipo de suporte (PK)
UnidadeId Integer - ID da unidade (FK)
TipSupNom String - Nome do tipo de suporte
TipSupStatus Enum - ATIVO, INATIVO
TipSupDtCadastro DateTime - Data de cadastro (gerado automaticamente)

Regras de Permissão por Perfil

👑 ADMINISTRADOR Acesso total a todos os tipos de suporte de todas as unidades
📋 GESTOR CRUD completo apenas nos tipos de suporte da sua própria unidade
🔧 TÉCNICO Visualização apenas (GET) dos tipos de suporte da sua unidade
👤 PESSOA Visualização apenas (GET) dos tipos de suporte da sua unidade
🔍 Observações Importantes:
  • Não há rota de DELETE - tipos de suporte não podem ser excluídos, apenas inativados
  • Todos os endpoints exigem autenticação via token JWT
  • Gestores só podem gerenciar tipos da sua própria unidade
  • Técnicos e Pessoas têm acesso apenas de leitura
  • A inativação de um tipo com chamados em andamento é bloqueada pela API

Códigos de Erro Específicos

400 Campos obrigatórios faltando, status inválido, ID inválido
401 Token não fornecido ou inválido
403 Gestor inativo, unidade inativa, permissão negada, transição de status inválida
404 Tipo de suporte, unidade ou gestor não encontrado
409 Conflito - Já existe um tipo com o mesmo nome na unidade
500 Erro interno do servidor
📌 Nota Importante: A API não possui rota de DELETE para tipos de suporte. A exclusão lógica é feita através da alteração de status para INATIVO.
